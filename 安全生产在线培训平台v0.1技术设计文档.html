〇、文档说明

本文档是《安全生产在线培训平台 v0.1 产品设计文档》的技术实现方案，面向开发与运维人员，回答三个问题：在约 400 人的企业规模下，系统怎样以最低成本跑起来（选型与架构）；学时数据怎样做到可信、可追溯（核心引擎与数据设计）；将来升级到 v0.2 及以后时，哪些钱现在就要花、哪些钱坚决不花（升级路径）。

一句话总纲：用"单机 + 轻栈"承接 400 人规模，把复杂度预算全部花在"学时可信"上，其余一切从简；同时通过少量低成本的结构预留（版本化 API、ORM 抽象、字段预留），把未来升级变成"加表加模块"，而不是"推倒重来"。

一、规模评估与容量测算（400 人）

技术方案的规模取决于"最坏的一天"，而不是平均的一天。安全培训的典型高峰是节前教育、事故通报后的专项学习——全员被要求限期完成，会在几天内挤在一起学。按此场景做保守测算：

容量测算：按集中学习最坏场景估算
指标 估算值 测算依据
注册用户 400 企业全员（含项目部／班组），单次 Excel 导入
日活跃学员 100 ~ 200 限期完成场景下约 25% ~ 50% 的人当天要学
峰值同时在线 80 ~ 120 班前会 / 午休 / 傍晚集中学习，按日活的一半估
心跳写入峰值 约 8 QPS 每人每 15 秒一次心跳，120 人 ÷ 15s ≈ 8 次/秒
文档下载峰值 瞬时 ~200MB 100 人同时打开平均 2MB 的 PDF，千兆内网可承受
课程库总量 数百个文件，< 5GB 文档类课程，单文件 1 ~ 30MB
年数据增量 < 1GB（数据库） 400 人 × 每年 40 学时 × 心跳明细，估算约 500 万行/年以内

结论：8 QPS 的写入峰值对 SQLite（WAL 模式，实测可承受每秒百次级写入）有十倍以上余量；文档并发下载是网络问题而非计算问题，千兆内网即可。因此 v0.1 采用"单台服务器 + 单应用进程"架构，不引入缓存、消息队列、负载均衡——这些组件在 400 人规模下只会增加部署与运维成本，不产生任何收益。

二、总体架构

图 1 · v0.1 系统分层架构（单机单进程，四层结构）
  • 进程模型：Uvicorn 单进程 + 异步 IO。SQLite 为单写者模型，多进程反而引入写锁竞争；单进程异步足以承载 8 QPS 心跳与并发文档下载，也让"课程文件扫描、定时备份"等任务可直接用进程内定时器实现，省掉独立的任务系统。
  • 会话状态：登录会话用服务端签名 Cookie（HttpOnly），不在数据库里存会话表——重启不丢状态、无缓存依赖；下文认证层抽象保留了将来改 Token / 对接统一身份的接口。
  • 静态与 API 同进程：两张 H5 页面由同一 FastAPI 进程的 StaticFiles 托管，部署单元只有一个目录 + 一个服务，"拷贝即部署"。

三、技术选型与理由

选型原则：每引入一个组件，都必须回答"不用它会坏吗"
层面 选型 理由 对升级成本的影响
运行时 Python 3.12 与团队现有环境一致，标准库 + FastAPI 生态成熟 无绑定风险
Web 框架 FastAPI + Uvicorn 异步原生，心跳类高频小请求开销低；自带 OpenAPI 文档便于联调 标准 ASGI 接口，可平滑替换服务器
数据库 SQLite（WAL 模式） 8 QPS 写入余量十倍以上；单文件备份、零运维；无独立数据库服务 经 ORM 抽象，迁移 PostgreSQL 预估 2~3 人日（见第十一节）
ORM / 数据访问 SQLAlchemy 2.0 屏蔽 SQLite 与 PostgreSQL 方言差异；迁移脚本成熟 这是本次最重要的升级预留
前端 原生 H5（HTML/CSS/JS），无框架无构建 2 张页面、零依赖、双击即用；不存在 npm 供应链与构建链维护成本 页面少，即使将来重写成本也可控
认证 服务端签名 Cookie（HttpOnly + SameSite） 内网 H5 最简单可靠的方案；itsdangerous 签名，无会话表 认证走独立模块接口，可替换为 LDAP/AD 适配器
密码哈希 passlib + bcrypt 行业标配，抗暴力破解 无
Excel 处理 openpyxl（读写 xlsx） 名册导入、台账导出均为 xlsx；纯 Python 无 Office 依赖 无
文档预览 浏览器原生 PDF 渲染 + PDF.js 本地化兜底 手机浏览器原生支持 PDF；PDF.js 单文件本地引用，处理老机型 上视频时播放器为独立组件，互不影响
定时任务 进程内 asyncio 定时器 文件扫描、每日备份两个任务，独立调度系统（如 Celery）纯属过度设计 任务函数独立成模块，可平移

明确不引入的组件（400 人规模下的反优化清单）：Redis / Memcached（无热点读压力）、消息队列 Celery（无异步任务量）、Nginx 强制部署（Uvicorn 直连即可，Nginx 仅作为可选的 HTTPS 终结点）、Docker/容器编排（单机内网服务，Windows 服务 / systemd 更省事）、前端框架 React/Vue（两张页面，构建链成本大于收益）、微服务拆分（单进程模块化已足够）。

4.3 索引与数据规则

  • 索引： users.employee_no（唯一）、 courses.file_name（唯一）、 study_records(user_id, course_id)（唯一）、 study_sessions(user_id, started_at)、 study_sessions(record_id)——台账导出按人查明细，两个索引覆盖全部查询路径。
  • 时间统一存 UTC ISO8601 字符串，展示层转本地；避免 SQLite 时区歧义。
  • 外键开启（PRAGMA foreign_keys=ON）；离职停用不删行，学时历史永久保留。
  • 心跳明细不入库：15 秒级心跳本身不落表（量太大且无审计必要），落库的是"学习段"（session）级别的汇总明细——审计粒度到"某天某时段学了多久、弹窗响应如何"，足够应对检查，又比逐心跳存储小两个数量级。
  • 数据修正原则：study_sessions 不可修改；确需修正口径时，由管理员在导出环节说明，或在 v0.2 引入带留痕的 adjustment 表。

5.1 心跳协议（学习引擎核心报文）

# 请求：前端每 15 秒一次
POST /api/v1/study/heartbeat
{
  "session_id": 1024,
  "last_position": {"page": 12, "ratio": 0.45},
  "visible": true          # 页面当前是否前台可见
}

# 响应：服务端返回权威累计值，前端只做展示不自行累计
{
  "gained_seconds": 15,        # 本次心跳认可的有效秒数
  "total_seconds": 1860,       # 该课程累计有效秒数（服务端口径）
  "required_seconds": 7200,    # 达标线（来自课程配置）
  "completed": false,
  "challenge": null            # 需要弹窗时返回 {"token": "c-8f3a", "timeout_s": 120}
}
  • 所有接口返回统一包裹结构 {"code": 0, "data": ..., "msg": ""}；错误码分段：4xxx 客户端（如 4101 未登录、4202 弹窗超时）、5xxx 服务端。
  • 心跳接口幂等且服务端权威：间隔合法性、弹窗状态、单日上限全部由服务端裁决，前端传值仅作参考。
  • 管理端导出接口直接流式返回 xlsx 文件，同时在 export_logs 落一条记录。

六、学习引擎设计（计时 / 防挂机 / 断点）

6.1 计时口径：服务端权威计时

有效学时完全不信任前端时钟。前端每 15 秒发一次心跳，服务端以"收到心跳的服务端时间差"为唯一计时依据：

# 单次心跳的有效时长计算（服务端逻辑）
delta = now_server - last_heartbeat_at        # 服务端时钟差
if delta <= 0:            gained = 0           # 时钟回拨/重放，不计
elif delta > max_gap:     gained = 0           # 断线超长间隔（默认 60s），本段不计
elif session_paused:      gained = 0           # 弹窗超时暂停期间，不计
else:                     gained = delta       # 正常：15s 间隔计 15s
total_seconds += min(gained, daily_remaining) # 单日计入上限默认 8 小时
  • 切屏暂停：前端监听 visibilitychange 与 blur，页面不可见即停发心跳；服务端超过 max_gap 收不到心跳自动结束该学习段（end_reason=timeout）。前后端双保险。
  • 断网容忍：前端把发送失败的心跳缓存在内存，恢复后携带 since 时间戳重发；但服务端只认连续性——中断超过 max_gap 的部分照例不计，断网不白学也不虚增。
  • 单日上限：每人单日计入学时默认上限 8 小时（可配置），防"挂夜"刷学时；这也是检查时最常被问的口径。

6.2 防挂机：随机挑战状态机

弹窗是学时可信的关键机制，状态机设计如下：

  • 触发：服务端在心跳响应中按随机间隔（90~180 秒，可配置）下发 challenge 令牌，前端收到即弹出"我在学习"确认框。
  • 应答：学员点击确认 → 前端调 /study/confirm 携带令牌 → 服务端校验令牌有效且未超时（默认 120 秒）→ 计时继续。
  • 超时：120 秒未确认 → 会话进入 paused 状态，此后心跳的 gained 一律为 0；重新确认后恢复。本段 confirm_miss 加 1，台账中可见。
  • 防作弊细节：令牌服务端生成、一次性使用、与会话绑定；确认间隔过短（如 1 秒内连续应答）视为异常但不惩罚，只记录——v0.1 保持"记录可查"而非"逻辑反作弊"，避免误伤真实用户。
  • 参数全部进配置文件：触发间隔、应答时限、单日上限、心跳间隔。检查口径变了改配置，不改代码。

6.3 断点续学与达标判定

  • 断点 = PDF 页码 + 滚动比例，随心跳上报写入 study_records.last_position；下次进入课程从断点打开。
  • 达标判定在服务端： total_seconds >= required_minutes × 60 时，记录置为 completed 并写入达标时间；之后继续学习仍累计（超额学时也如实记录），但状态不再变化。
  • 文件被替换导致课程重新登记时，同名课程的累计记录保留（视为同一课程的新版本），达标状态按新配置重新判定。

七、课程库与文件处理

  • 目录即课程库：课程根目录 data/courses/，支持子目录按"项目部/主题"分一层（子目录名作为课程分类导出列，仅此一层，不递归更深）。
  • 扫描机制：进程内定时器每 5 分钟扫描一次 + 管理端手动触发。以文件名为唯一键：新文件登记上架；文件被修改（mtime/hash 变化）更新指纹并保留学习记录；文件消失则下架（不删课程行，历史学时保留）。
  • PPT 处理（v0.1 约定）：浏览器无法直接预览 PPT，v0.1 约定"管理员统一另存为 PDF 后放入"；服务端自动转换（LibreOffice headless）作为可选开关，默认关闭——它给部署增加一个外部依赖，不符合"最小可用"原则，留待 v0.2 评估。
  • 下载安全：文件路径由数据库 id 解析，接口不接受用户输入的路径参数，杜绝路径穿越；下载走流式响应并支持 Range（手机阅读器分页加载大 PDF）。
  • 类型与大小限制：仅 .pdf 入库；单文件上限 100MB（可配置）；非白名单扩展名扫描时跳过并记录日志。

八、配置设计

所有"法规会变、口径会调"的参数一律进配置文件（config.yaml），启动加载、改动重启生效。配置即合规口径的唯一定义点：

# config.yaml —— 学时规则与运行参数
server:
  host: 192.168.10.50        # 内网监听地址
  port: 8000

  heartbeat_interval_s: 15    # 前端心跳间隔
  max_gap_s: 60               # 超过此间隔的心跳差值不计学时
  challenge_min_s: 90         # 防挂机弹窗随机下限
  challenge_max_s: 180        # 防挂机弹窗随机上限
  challenge_timeout_s: 120    # 弹窗应答时限，超时暂停计时
  daily_cap_hours: 8          # 单日计入学时上限

  initial_password: employee_no   # 初始密码=工号
  force_change_password: true     # 首登强制改密

  allowed_ext: [pdf]
  max_file_mb: 100
  scan_interval_min: 5

backup:
  daily_at: "02:30"           # 每日备份时间
  retain_days: 30

九、安全设计

  • 认证与会话：bcrypt 哈希存储；会话 Cookie HttpOnly + SameSite=Lax + 服务端签名（防伪造）；连续 5 次登录失败锁定 10 分钟；首登强制改密（初始密码=工号，全员工号在企业内半公开，必须改）。
  • 越权防护：学员端接口全部带 user 上下文，只能读写自己的学习数据；管理端接口统一 role=admin 依赖注入校验。
  • 文件安全：下载路径由 id 反查数据库，无用户可控路径；扩展名白名单；文件名在响应头做 RFC 5987 编码（中文文件名兼容）。
  • 台账防篡改：学习明细只增不改；累计值仅能由心跳引擎写入；导出留痕（export_logs）。达到"数据可解释、操作可追溯"——这是内网自用场景下合理的安全水位，不引入区块链式防篡改等过度设计。
  • 传输安全：默认内网明文 HTTP，边界由内网隔离保障；提供自签 HTTPS 的可选配置（建议启用，成本仅一张自签证书）。平台不出内网、无外网依赖。
  • 个人信息最小化：仅收集工号、姓名、部门；不留手机号等额外信息（字段仅预留、不入数据）。

十二、开发里程碑（3 周）

  1. 第 1 周 · 骨架与数据

    FastAPI 骨架 + 配置加载 + 5 张表建模；Excel 名册导入（含模板、去重、初始密码）；登录会话与首登改密；课程文件夹扫描上架。里程碑：管理员能导入名册、放入课程并在列表看到。

  2. 第 2 周 · 学习引擎（核心）

    课程列表页与 PDF 阅读（断点续学）；心跳计时 + 服务端口径；防挂机挑战状态机；切屏暂停与断网容忍；单日上限。里程碑：手机完成一次完整学习，断网、切屏、挂机三种场景计时全部正确。

  3. 第 3 周 · 台账与交付

    管理端总览页；个人明细/部门汇总两种 xlsx 导出 + 导出留痕；每日备份任务；NSSM/systemd 服务化部署；安全项收尾（锁定、路径穿越、HTTPS 可选）。里程碑：按产品文档三条验收标准逐条演练通过，试点一个项目部上线。

测试策略与里程碑并行：学习引擎的计时口径（间隔边界、弹窗暂停、单日上限、断网重放）全部写成自动化测试用例先行——这是全系统唯一"错不起"的模块，其余模块以接口联调 + 手工验收为主。
